#### **Q1. Write bash functions `marco` and `polo` that do the following: whenever you execute `marco` the current working directory should be saved in some manner, then when you execute `polo`, no matter what directory you are in, `polo` should cd you back to the directory where you executed `marco`. For ease of debugging you can write the code in a file `marco.sh` and (re)load the definitions to your shell by executing `source marco.sh`.**

**Answer :-**

```bash
marco() {
    export MAR_DIR={$PWD} ;
}
polo(){
    if [ -z "$MAR_DIR" ];
    then
    echo "Not executed" ;
    fi 
    cd $MAR_DIR ;
}
```

**Explanation** :- 

    - `export MAR_DIR={$PWD}` :- This will export the current working directory to the environment variable `MAR_DIR`. 
    - `if [ -z "$MAR_DIR" ] ; then echo "Not executed" ; fi` :- This will check if the environment variable `MAR_DIR` is empty. If it is empty, it will print "Not executed".
    - `cd $MAR_DIR` :- This will change the current working directory to the value of the environment variable `MAR_DIR`.

#### **Q1. Say you have a command that fails rarely. In order to debug it you need to capture its output but it can be time consuming to get a failure run. Write a bash script that runs the following script until it fails and captures its standard output and error streams to files and prints everything at the end. Bonus points if you can also report how many runs it took for the script to fail.**
```bash
 #!/usr/bin/env bash

 n=$(( RANDOM % 100 ))

 if [[ n -eq 42 ]]; then
    echo "Something went wrong"
    >&2 echo "The error was using magic numbers"
    exit 1
 fi

 echo "Everything went according to plan"
 ```

**Answer :-**

```bash
  count=0 ; 
while true 
do
count=$((count + 1)) ;
./command.sh>output.txt 2>error.txt
status=$? ;
if [$status -ne 0] ;
then
echo "Script failed after $count" ;
fi
echo "===========OUTPUT===============" ;
cat output.txt ;

echo "===========ERROR================" ;
cat error.txt ;
break ;
done

  
```

**Explanation** :- 

    - `count=0` :- Initialize a counter to 0.
    - `while true` :- Start a loop that will continue until it is broken.
    - `count=$((count + 1))` :- Increment the counter.
    - `./command.sh>output.txt 2>error.txt` :- Run the command and redirect its output to a file named output.txt and its error to a file named error.txt.
    - `status=$?` :- Get the exit status of the command.
    - `if [$status -ne 0] ; then echo "Script failed after $count" ; fi` :- If the exit status is not 0, print the number of runs it took for the script to fail.
    - `echo "===========OUTPUT================"` :- Print "===========OUTPUT================".
    - `cat output.txt` :- Print the output of the command.
    - `echo "===========ERROR================"` :- Print "===========ERROR================".
    - `cat error.txt` :- Print the error of the command.
    - `break` :- Break the loop.

#### **Q1. Start a `sleep 10000` job in a terminal, background it with `Ctrl-Z` and continue its execution with `bg`. Now use [`pgrep`](https://man7.org/linux/man-pages/man1/pgrep.1.html) to find its pid and [`pkill`](https://man7.org/linux/man-pages/man1/pkill.1.html) to kill it without ever typing the pid itself. (Hint: use the `-af` flags).**

**Answer :-**

```bash
sleep 10000 ;
# PRESS CTRL+Z AFTERWARDS
bg ;
pgrep -af sleep ;
pkill -f "sleep 10000" ;
```

**Explanation** :- 

    - `sleep 10000` :- Starts a process that will sleep for 10000 seconds.
    - `bg` :- Backgrounds the process.
    - `pgrep -af sleep` :- Finds the process id of the sleep command.
    - `pkill -f "sleep 10000"` :- Kills the sleep command.

#### **Q2. Say you don’t want to start a process until another completes. How would you go about it? In this exercise, our limiting process will always be `sleep 60 &`. One way to achieve this is to use the `wait` command. Try launching the sleep command and having an `ls` wait until the background process finishes.**
<br>

#### **However, this strategy will fail if we start in a different bash session, since wait only works for child processes. One feature we did not discuss in the notes is that the kill command’s exit status will be zero on success and nonzero otherwise. kill -0 does not send a signal but will give a nonzero exit status if the process does not exist. Write a bash function called pidwait that takes a pid and waits until the given process completes. You should use sleep to avoid wasting CPU unnecessarily.**

**Answer :-**

```bash
pidwait(){
    pid=$1 ;
    while kill -0 $pid 2>/dev/null
    do
    sleep 1 ;
    done

}
```

**Explanation** :- 

    - `pid=$1` :- The first argument is stored in the variable `pid`.
    - `while kill -0 $pid 2>/dev/null` :- The loop continues as long as the process with the given pid exists.
    - `sleep 1` :- The loop sleeps for 1 second to avoid wasting CPU.

#### **Q1. (Advanced) Write a command or script to recursively find the most recently modified file in a directory. More generally, can you list all files by recency?**

**Answer :-**

```bash
ls -l -R -s -t | head -3 | tail -1
```

**Explanation** :- 

    - `ls -l -R -s -t` :- Lists all files in the current directory and its subdirectories in long format, sorted by modification time.
    - `head -3` :- Takes the first 3 lines of the output.
    - `tail -1` :- Takes the last line of the output.
